# Commit

변경사항을 그냥 한 덩어리로 `git commit`하면 나중에 `git log`나 `git blame`으로 특정 변경의 이유를 추적하기 어렵다. 이 스킬은 커밋하기 전에 변경사항을 의미 단위로 쪼개고, 각 단위가 무엇을 왜 바꿨는지 알 수 있는 한국어 메시지를 붙이는 절차를 안내한다.

## 절차

### 1. 변경사항 파악

```bash
git status
git diff
git diff --staged
```

아직 커밋되지 않은 모든 변경(스테이징 여부와 무관하게)을 대상으로 한다. 스테이징되지 않은 변경이나 추적되지 않는 새 파일이 있다면, 분석을 위해 먼저 전부 스테이징한다:

```bash
git add -A
git diff --staged
```

git repository가 아니거나 변경사항이 전혀 없으면 그 사실을 사용자에게 알리고 멈춘다.

### 2. 논리적 단위로 분류

`git diff --staged`의 각 hunk를 읽고, "이 변경은 왜 존재하는가"를 기준으로 묶는다. 흔한 신호:

- 서로 다른 기능/버그를 건드리는 파일들은 별개 단위
- 같은 함수·컴포넌트를 고치는 여러 파일(구현 + 테스트 + 타입)은 보통 한 단위
- 포맷팅/린트성 변경과 실제 로직 변경은 분리 (섞여 있으면 로직 변경 쪽에 묶어도 되지만, 규모가 크면 별도 단위로)
- 관련 없는 파일이 우연히 같이 열려서 생긴 변경(예: 무관한 whitespace)은 그 자체로 하나의 잡일(chore) 단위

각 단위마다 어떤 파일/hunk가 속하는지 목록을 정리한다. 하나의 단위만 나오면 그대로 진행하면 된다.

### 3. 단위별로 스테이징하고 메시지 작성

전체를 한번에 add했으므로, 단위가 여러 개면 커밋 전에 다시 나눠서 스테이징해야 한다. 파일 단위로 깔끔히 나뉘면 `git add <files>`, 한 파일 안에서 섞여 있으면 `git add -p <file>`로 hunk 단위 선택을 사용한다. 나머지 단위는 그대로 남겨두고(unstaged) 다음 커밋 때 처리한다.

각 단위마다 커밋 메시지를 한국어 한 줄 요약으로 작성한다. 형식은:

```
<type>: <요약>
```

`type`은 변경 성격에 따라 고른다:

| type | 의미 |
|---|---|
| feat | 새로운 기능 추가 |
| fix | 버그 수정 |
| refactor | 동작 변화 없는 구조 개선 |
| chore | 빌드/설정/의존성 등 잡일 |
| docs | 문서만 변경 |
| test | 테스트 코드만 추가/수정 |
| style | 포맷팅 등 코드 의미에 영향 없는 변경 |

요약은 명령형으로 간결하게 쓰고("~함", "~추가" 같은 명사형 종결도 가능), 무엇을 바꿨는지 diff 내용에 근거해서 구체적으로 쓴다. "수정", "업데이트"처럼 내용 없는 요약은 피한다.

**예시**

입력 diff: `useAuth` 훅에 토큰 만료 시 자동 로그아웃 로직 추가
출력: `feat: 토큰 만료 시 자동 로그아웃 처리 추가`

입력 diff: `Button.tsx`의 잘못된 padding 값 수정
출력: `fix: Button 컴포넌트 padding 값 오류 수정`

### 4. 승인받고 커밋

커밋을 실행하기 전에, 계획한 커밋 목록(각 커밋에 포함될 파일과 작성한 메시지)을 사용자에게 보여주고 승인을 구한다. 여러 커밋이 예정되어 있다면 순서와 함께 전부 나열한다. 사용자가 메시지나 분류를 수정해달라고 하면 반영 후 다시 확인받는다.

승인을 받으면 계획한 순서대로 커밋한다:

```bash
git commit -m "<type>: <요약>"
```

여러 단위가 있다면 하나씩 스테이징 → 커밋을 반복한다. 모든 커밋이 끝나면 `git log --oneline -n <생성한 커밋 수>`로 결과를 보여준다.

## 하지 말아야 할 것

- 사용자 승인 없이 바로 커밋하지 않는다.
- `--no-verify`, `--amend` 등 훅 우회나 기존 커밋 수정은 사용자가 명시적으로 요청하지 않는 한 사용하지 않는다.
- 원격에 push하는 것은 이 스킬의 범위가 아니다. 별도로 요청받았을 때만 진행한다.
- 커밋 메시지에 diff 전체를 나열하거나 body를 붙이지 않는다 — 요약 한 줄이 이 스킬의 기본 형식이다.
